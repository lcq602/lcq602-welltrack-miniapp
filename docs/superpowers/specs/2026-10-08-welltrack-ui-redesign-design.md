# 健康管理小程序界面改版设计
日期：2026-10-08

## 问题与目标
现有页面重复使用相同白卡片，主要数据缺少层级，趋势与操作入口难以一眼理解。改版以“个人健康记录工具”为定位，让用户在手机上先看重点、再完成当天记录，并能清楚区分体重目标、习惯覆盖和统计数据。

## 方案比较
1. 仪表盘极简：只留体重和一条趋势，操作最少，但计划、习惯及运动数据被隐藏。
2. 全面卡片化：每项信息各一张卡，容易分块，但仍会显得像模板并增加滚动。
3. 健康科技风格（采用）：冷雾灰背景、墨蓝主卡、电光钴蓝主交互、荧光青柠强调；首页按体重/进度、今日行动、趋势分区，记录表按身体数据/日常状态/习惯分步呈现，分析页提供周/月摘要和可翻月日历。该方向用高对比建立数据层级，使用原生 WXML/WXSS 实现，不引入 UI 依赖。

## 页面与数据
- 首页：首屏突出当前体重和目标；维持模式隐藏误导性的线性减重进度，健康习惯显示近七天记录覆盖；提供记录和运动入口。
- 计划：目标类型、体重、日期和周安排可编辑后以新版本追加；星期键使用 API 的 mon–sun。
- 日常记录：分组采集体重/腰围、饮水/睡眠、饮食和习惯；防止空记录和提交中重复点击；清楚展示只读历史。
- 运动：活动类型使用独立 picker 数据，时长本地校验，列表清楚显示时间与备注。
- 分析：周/月统计采用趋势行展示，日历按自然月翻页；空数据有明确状态。
- 我的：集中个人目标、提醒、连接设置和 CSV/JSON 导出。

## 后端接口边界
保持 /api/v1 路由兼容，仅给 dashboard 增加 record_days_7d；weekly_completion 明确定义为近七天有记录天数/7。新增 API.md 列出会话、资料、首页、记录、运动、分析和导出端点。编辑/删除/导入仍不开放，遵循用户已确认的只读与新增授权。

## 验收
后端 API 测试覆盖新增统计字段和已有数据隔离/输入验证；小程序 JavaScript 语法、JSON 配置和 WXML 结构检查；微信开发者工具无法自动运行时明确标注模拟器验证边界。
