# 个人健康与体重管理小程序设计

日期：2026-10-08

## 目标与范围

交付可运行的微信原生小程序与 FastAPI + SQLite 后端。覆盖首次资料设置、目标计划、首页摘要、日常记录 CRUD、运动安排、日历/周月统计、CSV 导出、资料与提醒设置、JSON 备份恢复。提供无需 AppID 的本地开发身份，预留服务端微信登录凭证校验；不在客户端保存服务端密钥或直接连接 SQLite。

## 方案比较

1. 原生小程序 + FastAPI（采用）：单一服务端数据源，用户隔离及汇总规则统一，符合技术约束；需同步实现 API 和页面。
2. 小程序本地存储为主、后端同步：初始接口少，但双数据源会增加冲突、恢复和多设备复杂度。
3. 先做前端原型再接 API：视觉迭代快，但核心 CRUD 暂不可运行且存在模型脱节风险。

## 架构与数据流

小程序通过 `wx.request` 调用 `http://<开发机局域网地址>:8000/api/v1`。本地模式由 API 返回/持有开发用户身份；服务端在可信边界解析身份，并将当前用户 ID 显式传入所有数据查询。生产微信登录预留 `wx.login` code 换取会话的服务端接口，密钥通过环境变量注入。本地监听 `0.0.0.0:8000`，SQLite 文件位于后端数据目录并加入忽略规则。

实体包括用户资料与目标、阶段计划、每日记录、运动安排和提醒设置。每日记录按日期唯一归属用户，包含体重、腰围、饮食摘要、饮水、睡眠、习惯完成项；运动可独立多条记录并与日期关联。备份/恢复使用带版本号的 JSON，恢复时只写入当前用户范围并整体校验。

## 页面与 API 边界

首页读取 dashboard 汇总接口；计划接口读取/修改目标与每周安排；记录和运动分别提供分页/日期过滤及创建、编辑、删除；分析接口提供日历聚合、周报/月报；导出接口生成当前用户 CSV；我的接口管理资料/提醒及 JSON 备份恢复。所有写入均采用 Pydantic 校验与事务，所有读写均按认证用户过滤。危险医疗建议不属于产品范围；BMI 明确标为参考值，不诊断疾病，不承诺减重速度。

## 安全、性能与兼容

使用 SQLite 外键和必要索引；查询限制时间范围、分页并以聚合 SQL 生成报表，避免 N+1。CSV 对以公式字符开头的单元格做安全转义。开发身份仅用于本地；微信 code 校验配置缺失时明确禁用，不接受客户端声明任意 user_id。API 不返回密钥或 session key。数据库不提交，提供 `.env.example` 和 `uv.lock`。

## 验证

通过 FastAPI 测试覆盖首次资料、用户隔离、记录 CRUD、计划修改、统计、导出及备份恢复；运行后端测试与编译检查。前端检查 JSON/WXML/JS 配置和请求路径；若微信开发者工具不可用，则明确说明未进行真实模拟器验证。记录是否能量化 5% 性能约束；缺少基准时如实声明无法定量验证。

## 未纳入本轮

线上部署、微信审核/AppID 配置、医疗诊断与膳食处方、复杂社交及云同步。

## 数据写入授权边界

实施时用户确认仅允许读取与新增。故实际版本将用户资料/目标以追加版本保存；日常记录和运动只支持新增。记录编辑、删除及备份导入恢复会影响已有数据，暂不实现；CSV 和 JSON 导出保留。
